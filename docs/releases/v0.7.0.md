Read the odometer and the remaining range straight from the dashboard.

## New

- **Dashboard scan:** in the new fill-up form, tap **Scan cluster** and frame the instrument cluster. The app reads the total odometer and the remaining range as the phone holds steady on them, and **Use values** fills the form. Everything runs on the phone and frames are never saved. The camera is asked for only when you open the scan.
- **From a photo:** pick a photo of the cluster from the gallery. Values read that way are marked for checking.
- **Where the values sit:** each vehicle has its own 3x3 map in Settings. The odometer defaults to the bottom left and the range to the bottom right. Set it once and the scan follows.

## Changed

- The receipt scan still reads liters, price, total and date. The odometer and the range now come from the cluster scan.
- The database moves to version 4 with two columns on vehicles. Your data is kept, and existing cars get the bottom corners.

## Before you update, if you use cloud sync

Run these two lines once in the SQL editor of your Supabase project, before installing 0.7 on any phone that syncs:

```sql
alter table public.vehicles add column if not exists odometer_spot text;
alter table public.vehicles add column if not exists range_spot text;
```

Sync fails on unknown columns until they exist. The same lines are at the top of [docs/supabase/schema.sql](https://github.com/FrancescoCastaldi/fuel-ledger-android/blob/main/docs/supabase/schema.sql).

## Updating

This release is signed with the same key as 0.3.0 to 0.6.0 and installs over them. Exporting a CSV backup from **Settings** before updating is still a good habit.
